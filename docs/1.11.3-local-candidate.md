# Local 1.11.3 candidate

Prepared October 6, 2026 on `test/1.11.3-final-local`, based on private advisory
PR #5 (`0b4bc4c`). Includes the privately merged pinentry and fail-closed helper
changes plus the two October 4 reporter findings:

- Wait for the timed-out helper using Quickshell's `processId` property.
- Keep legacy PIN unlock busy until its process exits, preserving ownership
  of its held password when the panel closes and reopens.

Both regression tests failed before the fixes and passed after them.
The fixes and additional test coverage are follow-up commits for private
advisory PR #5 on `fix/reporter-pinentry-followups`. PR #5 remains open pending
the reporter's recheck and final release gates. No public merge, release or
advisory publication is part of this preparation.
The manifest still says 1.11.2 until release preparation; identify this candidate
by its private PR revision rather than the manifest version.

## Desktop acceptance checks

Use a disposable Bitwarden account for destructive or recovery checks.

1. Unlock by password and PIN. Try a wrong answer, cancel, kill pinentry, retry,
   and explicitly select panel typing. Confirm method selection and focus after
   each dialog. Repeat while fingerprint/FIDO2 are configured if available.
2. Open a master-password-reprompt item. Cancel and retry; open or close the
   panel during the prompt. Confirm it does not remain busy.
3. Reveal and hide a password and notes, copy without revealing, edit and save.
4. Lock through the panel and through `bw lock`. Confirm SSH signing stops;
   unlock again and confirm an approval is needed as expected.
5. Close/reopen during PIN unlock, switch accounts, and restart the shell.
   Confirm no unexpected unlock or stale result occurs.
6. Check quick-unlock disable/enable and keyring error notices using a test
   account. A real keyring failure must not be reported as successful cleanup.

The system pinentry wrapper prefers GNOME/GCR on this session; the live runner
recognizes both GNOME/GCR and native pinentry window classes. `pinentry-qt`
is also installed but was not forced for testing. Revealed values, setup fields and
explicit panel typing retain the documented shell-core exposure.
